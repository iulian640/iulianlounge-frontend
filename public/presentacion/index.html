Un club, dos formas de entrar

Lo decidí el 3 de julio: en un teléfono el 3D gasta batería y WebGPU no es fiable. La lógica es la misma; la presentación, propia de cada uno.

Demo

  1. Hacerse socio: la cuenta nace con 100 monedas.
  2. Pedir un French 75: bajan 40 monedas, el barman lo nota y subo a Cliente.
  3. Sentarse a la mesa: una mano de blackjack, de la apuesta al resultado.
  4. Lo mismo en el móvil: las dos salas, la carta y la charla con el barman.

Si la red falla, hay un vídeo grabado de los dos recorridos.

Arquitectura

Vue 3, Pinia, Vue Router, vue-i18n. Three.js para el 3D.

Caddy

HTTPS automático, sirve la app y reenvía /api al backend.

Spring Boot 4

Java 21, Spring Security con JWT, JPA. 15 endpoints REST.

PostgreSQL 17

En Docker. Esquema versionado con Flyway, de V1 a V7.

Mismo origen: la cookie de refresh viaja sin CORS. Claude Haiku, opcional y solo para la charla del barman.

Decisiones, por escrito

ADR-04

El saldo es un libro de cuentas

Cada movimiento es una fila nueva; nada se sobrescribe. El saldo se puede auditar línea a línea.

ADR-09

Monedas en enteros

Nunca double para el dinero: long en Java, bigint en la base de datos.

ADR-08

Dos tokens

Un JWT de acceso corto y un refresh en cookie httpOnly, que se borra al salir.

ADR-05

El barman no toca el dinero

El LLM conversa con los datos del socio, pero pedir y cobrar son deterministas.

ADR-06

El backend habla en claves

La API devuelve códigos; el frontend pone el texto en castellano o en inglés.

Seguridad y datos

  • Contraseñas con BCrypt; un hash falso cuando el usuario no existe, para no delatarlo por el tiempo de respuesta.
  • Límite de intentos en el login y el registro, y otro por socio en pedidos y apuestas.
  • La IP real del cliente detrás del proxy: Caddy quita las cabeceras que se podrían falsificar.
  • Pedidos y apuestas idempotentes: un doble clic no cobra dos veces.
  • La última defensa está en la base de datos: el saldo nunca baja de cero.
  • Página de privacidad y tope de gasto diario para el barman con LLM.

En producción

  • Un servidor ARM de Oracle Cloud en Madrid.
  • Docker Compose con tres servicios: PostgreSQL, el backend y Caddy con la app.
  • Certificado HTTPS de Let's Encrypt, que WebGPU necesita.
  • Antes de migrar la base de datos, una copia que guardo también en local.

Cómo trabajé con IA

  • Trabajé con Claude Code como compañero de programación: yo decidía qué construir y cómo, y revisaba cada cambio.
  • Las piezas que defiendo hoy las escribí aprendiendo, paso a paso, con la IA explicando en vez de resolver.
  • Cada pieza pasó por revisores automáticos de código y seguridad, y por mis pruebas en pantalla antes de entrar.

Lo que me llevo

  • Escribir las decisiones antes de programar ahorra discusiones conmigo mismo.
  • Los tests me dejaron cambiar el diseño del móvil a dos días de la entrega sin miedo.
  • Recortar a tiempo: el PMV es la barra, el blackjack y el barman; el resto espera.
