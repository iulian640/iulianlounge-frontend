¿Y si el pedido llega dos veces?

Pasa con un doble clic o con una red lenta que reintenta. El navegador manda cada pedido con una clave única. Si el servidor recibe otra vez la misma clave, devuelve el cobro que ya hizo en lugar de cobrar de nuevo. Además, la base de datos no deja guardar dos movimientos con la misma clave.

Base de datos

PostgreSQL en Docker. Las tablas se crean con migraciones de Flyway.

  • Cada usuario tiene una cartera con su saldo.
  • Cada cambio de saldo es una fila nueva en token_transaction: pedidos, regalos, apuestas y premios. Así nunca se pierde un movimiento.
  • El saldo no puede ser negativo: lo impide una restricción de la propia base de datos.
  • Las monedas son números enteros, sin decimales, para no tener errores de redondeo.

Seguridad

Contraseñas
Se guardan cifradas con BCrypt, nunca en texto plano. Si alguien robara la base de datos, no podría leerlas.
Login con JWT
Al entrar recibes un token de 15 minutos. Spring Security lo comprueba en cada petición.
Sesión
Para no pedir la contraseña cada 15 minutos hay un token de refresco en una cookie httpOnly, que JavaScript no puede leer.
Intentos
Máximo 20 por minuto en login y registro, para frenar a quien prueba contraseñas en bucle.
